## 3. 关键技术细节

### 3.1 草稿撤销弹窗（L1-L3 代码行）

**真实 DOM 结构**（弹窗出现在 `<body>` 根下，不在发布表单内）：
```html
<div>
  <div class="byte-message-wrapper byte-message-wrapper-top">
    <div class="message-slideDown-exit ...">
      <div class="byte-message byte-message-info">
        <svg ... class="info byte-icon byte-icon-info-circle-fill"></svg>
        <span>已恢复上次编辑未保存的内容
          <span class="wtt-publish-message-opr">撤销</span>   ← 精确点击目标
        </span>
      </div>
    </div>
  </div>
</div>
```

**`buildDismissRestoreTipScript` 检测 + 点击策略**：
- 最多 33 轮 × 300ms = 9.9s（字节系弹窗通常出现在页面加载后 1-3s，消失 5s 左右）
- 4 层兜底选择器：`span.wtt-publish-message-opr` → `div.byte-message-info span:last-child` → `.wtt-publish-message-opr` → 文本内容 "撤销"的 span
- 点击后再轮询一轮确认弹窗被关闭
- **重要**：撤销点击成功后立即调用 `buildClearDanglingImagesScript()`（清理草稿回显残留的编辑器图片 + 抽屉缩略图 + 预览区图片）

---

### 3.2 话题浮层推荐匹配（核心难点）

#### 为什么要「连续 2 轮 firstItemText 稳定」？

字节的话题接口是**异步 ajax** + **输入法 IME 未提交字符** + **ProseMirror composition 状态** 三者叠加。用户日志的典型 case：

```
用户输入：#硅谷
#1 探测轮：firstItemText="#硅# 252讨论"    ← 接口只回来了"硅"，"谷"还在 IME 未提交或接口还没返回
#2 探测轮：firstItemText="#硅谷# 1,395讨论" ← 接口返回完了
若立即 ready（第 1 轮就 break）→ match=false → 取消插入 = 正确话题被误伤
```

**解决方案**：必须连续 2 轮 firstItemText 完全一样才算就绪（`STABLE_NEED = 2`），第 1 轮记录 prev=「#硅…」，第 2 轮和 prev 不一样重置 stableCount=1，第 3 轮一致才通过。

#### 为什么「只按 1 次 Space，不按 ESC，不删文本」？

ProseMirror 的键盘映射：
- `ESC` = 取消当前正在编辑的 Mention token（composition cancel）→ **副作用**：如果前一个 token 刚插入还没完全 commit，会被一起回退掉（日志 case：#硅谷 点选成功 → #AI 不匹配按 ESC → #硅谷 也被撤了）
- 连续 2 次 `Space`：第二次 Space 在部分版本也有"取消上一个 atomic node"副作用
- JS scrub 文本（直接改 `node.nodeValue` 重新 setSelection）：selection 在复杂嵌套节点里会错位，**极端情况会把整个正文覆盖成空串**（用户已实际遇到过一次）

头条提示原文「敲空格可取消插入话题」是平台自己提供的官方语义，在浮层打开状态下按 1 次 Space = 取消本次插入而不影响其它内容，风险为 0。

### 3.3 图片重复 3 道防线（解决上传 1 张最终页面显示 2 张）

三道防线作用于三个不同阶段的三个独立位置：

| 阶段 | 位置 | 触发时机 | 清理对象 | 策略 |
|---|---|---|---|---|
| 防线 1 | 全局 | 撤销弹窗点击成功后立即执行 | 编辑器 ProseMirror img / figure + 抽屉 li + 预览缩略图全局 | 只点 X 图标，编辑器可直接 removeChild（ProseMirror 已撤销，不是 Vue 组件） |
| 防线 2 | 抽屉内 | 抽屉 ready 后、点确定之前 | `li.pic-select-image-item-wrap` 含 `.success` 的已上传项 | 倒序保留最后 N 张，前面的点 `.image-item-remove`（绝不 removeChild → 破坏 Vue 会导致确定按钮一起消失） |
| 防线 3 | 预览缩略图区 | 抽屉关闭 + 插入结果检测后 | `div.upload-list > div.img-box-item` | background-image URL（去 query 签名）去重，同 URL 只留第 1 张，其余点 `i.image-remove-btn` |

**防线 2 的踩坑记录**：

第一版加了 `if(!done) item.parentNode.removeChild(item)` 作为点不到 X 的兜底，用户日志出现：
```
清理抽屉多余图: beforeCount=4, removed=3, afterCount=0   ← 全删光了
点击确定: clicked=false, reason="no-confirm-btn-in-drawer" ← 整个 footer 被 Vue 卸载，确定按钮消失
```

结论：**字节的 Vue 组件抽屉 绝对不能手动 removeChild**，会破坏内部 v-for key 跟踪 → 整段 footer 卸载。宁可不删也不硬删。

**防线 3 的 DOM 精确匹配**（用户亲自提供的真实结构）：
```html
<div class="upload-list">
  <div class="img-box-item">                       ← 第1张（保留）
    <span class="item" style="background-image: url('https://...同 URL...')"></span>
    <i class="image-remove-btn"></i>
  </div>
  <div class="img-box-item ml6">                    ← 同 URL 重复（点 i.image-remove-btn）
    <span class="item ml6" style="background-image: url('https://...同 URL...')"></span>
    <i class="image-remove-btn"></i>
  </div>
  <div class="upload-handler ml6">                 ← .img-box-item 选择器不匹配 + 添加按钮，完全安全
    <span class="upl-btn image-add-btn">+</span>
  </div>
</div>
```
选择器严格 `div.upload-list > div.img-box-item`（div 且 img-box-item，不是 upload-handler），URL 去掉 `?` 签名（不同 expires 算同一张），重复的只点 `i.image-remove-btn` 走组件自己的删除逻辑。

### 3.4 脚本安全构造（JS SyntaxError 防护）

所有 DOM 操作脚本**统一用 TS 字符串 `s += '...'` 安全拼接**，绝不使用模板字符串内嵌正则 / 反斜杠：

| 避免触发 SyntaxError 的规则 | 说明 |
|---|---|
| 单引号 `'` 用 `var q = '\''` 变量 | 避免多层引号嵌套错配 |
| 正则、`\s`、`\b` 反斜杠序列 | 能不用就不用（如 ClearDanglingImagesScript 直接删掉"空文本段落判断"那段正则判断） |
| 必须用正则的地方（url match） | 单独写在一行 JS 字面量里，不在字符串拼接里传反斜杠变量 |
| 所有 try/catch 在最外层 + 每个循环体内 | 单个节点异常不影响其它节点，永远返回对象（不 throw） |
| 返回结果带 `fatal` 字段 | JS 侧语法/运行时错误直接写进 fatal，主进程通过 catchNull 二次保护 |

## 4. 话题匹配规则

`firstItemText` 标准化流程：
```
原始:  "#硅谷# 1,394讨论"
  │ ① 去所有 # 和 ＃
  ▼
中间:  "硅谷 1,394讨论"
  │ ② 去末尾 数字+（讨论|人|条|个|篇|阅读|万|亿|k|K|M|G）
  ▼
标准化 normalized = "硅谷"
用户输入 tagName = "硅谷"
```

| 匹配档 | 判定 | Case |
|---|---|---|
| 强匹配 | `normalized === tagName` | `#硅谷` → first = "#硅谷# 1,394讨论" → ✅ |
| 前向匹配（严格） | `normalized.startsWith(tagName)` 且 next 字符**不是**字母数字中文 | `#AI` → first="#AI/ML 研究# 5讨论" → normalized="AI/ML 研究" → pre="AI"，next='/'（不是字）→ ✅ |
| 不匹配 | 上面两档都不满足 | `#AI` → first="#AI数据中心…活靶子# 13讨论" → normalized="AI数据中心…活靶子" → pre="AI"，next='数'（中文/字）→ ❌（是用户没想要的扩展话题） |

**不匹配后的处理**：只按 1 次 Space（官方取消语义），统计 `fallback=0, handled=0`，不计数、不删文本。

| ❌ 禁止做法 | 实际后果 | ✅ 正确做法 |
|---|---|---|
| 话题不匹配按 `ESC` 取消 | ProseMirror 回退撤销，刚插入的前一个话题一起没了 | 严格按官方提示，只按 **1 次 Space** |
| 话题不匹配用 JS 改 nodeValue 删 `#xxx` 文本 | selection 在复杂嵌套结构里错位 → 整个正文被清空 | **完全不要 JS 删文本**，Space 语义足够 |
| 话题浮层 firstItemText 首次出现就立即 break | 字节接口异步返回半截字，正确话题被误判不匹配 | 连续 2 轮 firstItemText 完全一致才 ready（稳定判定） |
| 抽屉清理脚本宽泛匹配 `li, [class*="image-item"]` | footer 元素也算进来 → `beforeCount=4` | **只用** `li.pic-select-image-item-wrap` 精确类名 |
| 抽屉清理点不到 X 就 `removeChild()` 兜底硬删 | 破坏 Vue 内部 v-for key 跟踪 → 确定按钮一起卸载消失 | 宁可不删也不硬删，只点 `.image-item-remove` 走组件自己逻辑 |
| 用模板字符串 `` `...${bs}s+...` `` 拼正则 | Electron 下反斜杠容易触发 JS SyntaxError → catchNull | 正则判断能删就删（如 clear 脚本空段落判断直接删掉），保留的正则用字面量单行写 |
| upload-list 去重脚本选择器含 `.upload-handler` | 添加按钮被点 X 删掉 | 严格 `div.img-box-item`（类名不等于 upload-handler） |
| clear-dangling-images 返回 totalRemoved=-1 | 脚本 SyntaxError 被吞，无法定位哪段错 | 所有脚本最外层 try/catch 都返回 fatal 字段，主进程 catchNull=true 时额外 warn 打印 errStr |
