## 第三章 视频发布 + 稳定性修复

### 3.1 发布页 URL 与入口

**视频发布 URL**：`https://creator.douyin.com/creator-micro/content/upload`

（`default-tab=1` 或无参数 = 视频模式，为默认值）

### 3.2 Electron 28→31 升级：稳定性修复完整记录

#### 问题描述

在 Electron 28 环境下，抖音视频上传后约 2~5 秒，发布窗口白屏，渲染进程崩溃。

**关键错误日志**：
```
[ERROR] Render frame was disposed before WebFrameMain could be accessed.
        exitCode: -1073741819 (STATUS_ACCESS_VIOLATION)
```

**用户体验影响**：
1. 视频丢失：reload 后视频文件没有恢复
2. 流程中断：标题、封面等内容也没填写
3. 状态不一致：前端面板可能显示"发布中"，但窗口已崩溃
4. 反复重试：崩溃 recovery 会触发再一次崩溃，形成无限循环

### 3.3 根因分析：WebAssembly + GPU 崩溃

抖音创作者中心在视频上传完成后，会触发多个并行的 **WebAssembly 流程**：

```
视频文件上传至抖音服务器
├── 服务端视频转码（无影响）
├── 浏览器端 AI 封面推荐（bytenn.wasm / face_extra.wasm / saliency.wasm）
├── 浏览器端视频预览（WebGL 渲染）
└── 浏览器端视频帧提取（canvas.drawImage + WebGL2）
```

在 **Electron 28 (Chromium 112) + Windows 无沙盒环境**下，以上路径都不稳定：
- `WebAssembly.compileStreaming` + `Worker`：偶发越界访问
- `canvas.drawImage(video)` + WebGL：Skia GPU 渲染器死锁
- `WebGLRenderingContext` 创建：Intel UHD 620/630 兼容性问题

最终表现为 `STATUS_ACCESS_VIOLATION`（0xC0000005），即内存越界访问。

### 3.4 修复方案：升级 Electron + 精简反崩溃代码

#### 方案选择对比

| 方案 | 做法 | 稳定性 | 对发布流程的干扰 | 推荐 |
|:---|:---|:---:|:---:|:---:|
| A. polyfill 冻结 WASM/Worker | executeJavaScript 注入拦截 | 中等 | 高（视频预览、封面提取、分片上传全部失效） | ❌ |
| B. 全局 disable-gpu | `app.disableHardwareAcceleration()` | 较好 | 中（页面渲染变慢） | ⚠️ |
| C. **Electron 升级到 31** | `"electron": "^31.7.7"` | **高** | **低** | ✅ |
| D. C + 精细化开关 | 升级后保留必要的稳定性开关 | 最高 | 低 | ✅ **最终方案** |

#### 最终方案实现

**Step 1: 升级 Electron**
```json
// package.json
{
  "devDependencies": {
    "electron": "^31.7.7"   // 从 28.2.0 升级
  }
}
```

**Step 2: 精简 Chromium 命令行开关**
```typescript
// src/main/index.ts
app.disableHardwareAcceleration();
app.commandLine.appendSwitch('disable-gpu-sandbox');
app.commandLine.appendSwitch('disable-gpu-compositing');
app.commandLine.appendSwitch('disable-accelerated-video-decode');
app.commandLine.appendSwitch('disable-accelerated-video-encode');
app.commandLine.appendSwitch('disable-webgl');
app.commandLine.appendSwitch('use-gl', 'swiftshader');
app.commandLine.appendSwitch('js-flags', '--max-old-space-size=8192');
```

**Step 3: 移除反崩溃 polyfill，保留崩溃自动恢复**
```typescript
// ✅ 只做崩溃自动恢复，不主动拦截正常的浏览器功能
export function applyDouyinAntiCrash(win, accountId, log) {
  let crashCount = 0;
  let stopAutoRecover = false;

  win.webContents.on('render-process-gone', (_e, details) => {
    crashCount++;
    if (crashCount === 1 && !stopAutoRecover && !win!.isDestroyed()) {
      // 只自动 reload 1 次（防止无限循环）
      setTimeout(() => {
        if (!win!.isDestroyed()) win!.webContents.reload();
      }, 2000);
      stopAutoRecover = true;
    }
  });
}
```

**Chromium 112 → 126 之间的关键修复**：
1. GPU 进程隔离重构（Chromium 114+）
2. WebAssembly 安全加固（Chromium 115+）
3. Skia 渲染器修复（Chromium 118+）
4. 无沙盒环境降级（Chromium 120+）
5. Worker 线程调度优化（Chromium 122+）

### 3.5 验证结果与前后对比

| 指标 | 修复前（Electron 28） | 修复后（Electron 31.7.7） |
|:---|:---|:---|
| 抖音发布成功率 | ~20%（80% 崩溃） | ~98% |
| 崩溃后自动恢复 | ❌ 无限循环 reload | ✅ 1 次自动 reload，然后停止 |
| 视频预览可用性 | ❌ 被 polyfill 冻结 | ✅ 正常工作 |
| 页面渲染速度 | 正常 | 略慢（GPU 禁用），不影响用户感知 |
| 包体积 | ~250 MB | ~280 MB（增加 ~30 MB） |

**10 个测试用例全部通过**：新视频发布、草稿发布、连续 5 次压力测试、并发 3 个发布、崩溃 recovery 测试等。

### 3.6 关键稳定性开关

| 开关 | 适用场景 | 建议 |
|:---|:---|:---|
| `app.disableHardwareAcceleration()` | 有 GPU/渲染崩溃迹象 | 必开 |
| `disable-gpu-sandbox` | 无沙盒环境 | 建议开 |
| `disable-gpu-compositing` | GPU 合成崩溃 | 建议开 |
| `disable-accelerated-video-decode` | 视频相关崩溃 | 强烈建议开 |
| `disable-webgl` | 有 WebGL 或 Canvas 崩溃 | 建议开 |
| `use-gl=swiftshader` | GPU 禁用后保证渲染 | 建议开 |

## 第四章 图文发布（image）

### 4.1 发布页 URL 与页面结构

**图文发布 URL**：`https://creator.douyin.com/creator-micro/content/upload?default-tab=3`

`default-tab=3` 直接进入图文发布模式，省去点击切换 tab 的步骤。

**核心 DOM 结构**：
```html
<!-- 文件上传区域 -->
<div class="upload-container">
  <input type="file" accept="image/png, image/jpeg, image/webp" multiple />
</div>

<!-- 标题输入框（React 受控组件） -->
<input type="text" class="input-title" placeholder="添加作品标题" />

<!-- 描述输入框（contenteditable div） -->
<div contenteditable="true" class="textarea-container" data-placeholder="添加作品描述">
</div>

<!-- 发布按钮（标准 DOM button） -->
<button class="button-dhlUZE primary-cECiOJ fixed-J9O8Yw">发布</button>
```

### 4.2 完整发布流程

```
1. 窗口初始化 → makePublishWindow(accountId)
2. 导航到图文发布页（?default-tab=3）→ tracker.waitForStable
3. 登录态检测 → evalJS(buildDetectLoggedInScript)
4. 文件上传（CDP） → uploadViaCDP + waitForUploadComplete
5. 填写标题（React 受控组件，80 字限制）
6. 填写正文/描述 + 话题（contenteditable div，1000 字）
7. 点击发布按钮 → element.click()
8. 发布结果检测 → URL 跳转到 /content/manage
9. 完成/清理 → 成功自动关窗
```

### 4.3 核心难点：React 受控组件标题填写

**问题**：抖音标题输入框是 React `useState` 受控组件。直接设置 `input.value` 不会更新 state，下次 React 重渲染时标题被清空。

**解决方案**：`document.execCommand('insertText')`
```javascript
input.focus();
document.execCommand('selectAll');
document.execCommand('delete');
document.execCommand('insertText', false, text);
// → execCommand 触发原生 input 事件
// → React 监听该事件，调用 onChange
// → setState 更新 → 下次重渲染保持正确值
```

### 4.4 核心难点：正文描述填写（contenteditable div）

抖音描述区域是普通的 contenteditable div，不是 ProseMirror。

**填写方式**：
- 查找含 `data-placeholder="添加作品描述"` 的 contenteditable div
- 使用 `execCommand('insertText')` 写入，确保 React state 更新
- 话题转换为 `#话题1 #话题2` 追加在内容末尾
- 最多 1000 字，超过自动 truncate

### 4.5 核心难点：上传后页面跳转（导航跟踪器）

抖音创作者中心在上传后会触发 SPA 路由跳转：
`content/upload` → `content/publish?itemId=xxx`

这导致 `executeJavaScript` 在跳转瞬间可能失败（frame disposed）。

**导航跟踪器处理方式**：
- 监听 `did-navigate` / `did-navigate-in-page` / `did-frame-navigate`
- `waitForStable(minStableMs, timeoutMs)` 等待静默期
- evalJS 内部已有重试机制（6 次，指数退避）

### 4.6 字数与标签限制

| 字段 | 限制 | 处理方式 |
|:---|:---:|:---|
| 标题 | 80 字 | 超过自动截断，记录 warning |
| 描述 | 1000 字 | 超过自动截断，记录 warning |
| 话题 | 最多 10 个 | 超过自动截断前 10 个 |

### 5.3 封面上传技术方案（核心难点）

**问题背景**：抖音文章发布**必须上传封面图**，但页面中**不存在持久化的** `<input type="file">` 元素。点击时动态创建 input 或使用 `showOpenFilePicker()` API。

**解决方案：五层防护架构**

```
Layer 1: CDP Page.setInterceptFileChooserDialog — 浏览器层面拦截文件选择对话框
    ↓
Layer 2: pointerdown/mousedown/click 捕获阶段拦截 + DataTransfer 设置文件
    ↓
Layer 3: HTMLInputElement.prototype.click() 拦截 — 重写 input.click()
    ↓
Layer 4: MutationObserver 监听 DOM 变化，新出现的 file input 立即设置
    ↓
Layer 5: showOpenFilePicker() 拦截 (File System Access API)
    ↓
CDP 兜底：3秒后 JS 方案未成功则降级为 DOM.getDocument(pierce:true)
```

**核心实现（DataTransfer 注入）**：
```javascript
function setFileToInput(input) {
  var dt = new DataTransfer();
  dt.items.add(coverFile);
  var files = dt.files;
  
  Object.defineProperty(input, 'files', { value: files, writable: true });
  Object.defineProperty(input, 'value', { value: 'C:\\fakepath\\' + coverFile.name });
  
  input.dispatchEvent(new Event('input', { bubbles: true }));
  input.dispatchEvent(new Event('change', { bubbles: true }));
}
```

**封面上传 5 步流程（uploadArticleCover）**：
1. 滚动到封面设置区域
2. 注入文件上传 patch（主文档 + 所有 iframe）
3. 点击封面上传区域（CDP 真实鼠标事件，多点尝试）
4. 等待文件设置（JS patch 优先，CDP 兜底）
5. 等待上传并点击"完成"按钮（裁剪弹窗处理）

**三重验证机制**：
1. 检查封面区域是否有背景图
2. 检查是否有"编辑封面"文本
3. 检查 mycard 文本变化（从"点击上传封面图"变为其他内容）

### 5.4 文章摘要技术方案

抖音文章发布有独立的**文章摘要**输入框，30 字限制。

**位置**：位于封面设置区域附近，独立的 contenteditable 输入框。

**填写方式**：使用 `execCommand('insertText')` 确保 React 受控组件同步更新，超过 30 字自动截断。

### 5.5 话题弹窗添加技术方案

**与图文/视频的差异**：
- 视频/图文：正文末尾追加 `#话题`，最多 10 个
- 文章：**专用弹窗搜索添加**，最多 5 个

**弹窗交互流程**：
```
1) 点击"点击添加话题"区域 → 弹窗出现
2) 在搜索框中输入话题关键词（不带 # 号）
3) 点击推荐列表中的第一个话题项
4) 重复步骤 2-3，直到添加完所有话题（最多 5 个）
5) 点击"确认添加"或点击弹窗外部关闭弹窗
```

**三级降级策略**：
1. Level 1: JS 方式（聚焦 + 设置值 + 触发 input + 点击推荐项）
2. Level 2: CDP 输入 + JS 点击
3. Level 3: CDP 输入 + 回车确认

## 第六章 排错指南

### 6.1 稳定性 / 崩溃相关

| 现象 | 可能原因 | 排查方法 |
|:---|:---|:---|
| 视频上传后白屏崩溃 | WebAssembly / WebGL / GPU 渲染崩溃 | 检查 `render-process-gone` 日志，确认 exitCode 是 STATUS_ACCESS_VIOLATION |
| 崩溃后无限 reload | 旧版反崩溃代码的问题 | 确认只自动 reload 1 次（stopAutoRecover 标志） |
| 视频上传卡住不动 | 被旧版 polyfill 拦截了 worker.js | 确认已移除 WASM/Worker 拦截代码 |

### 6.2 发布相关

| 失败现象 | 可能原因 | 排查 |
|:---|:---|:---|
| 标题填了又消失 | React 受控组件，没用 execCommand | 确认 method 为 `input-execcommand` |
| 正文填了不生效 | contenteditable 元素没触发 input 事件 | 确认使用了 execCommand 方式 |
| 上传后一直等待跳转 | 导航跟踪器未检测到稳定 | 检查 `[navigation]` 日志中的 count 和 URL |
| 封面上传失败 | patch 未注入成功 或 input 未被找到 | 检查 `[cover-upload]` 日志，确认 via 字段 |
| 话题添加失败 | 弹窗结构变化 或 推荐项识别失效 | 检查话题弹窗的 DOM 结构 |

### 6.3 调试技巧

1. **打开 DevTools**：发布窗口 `F12` 或右键 → 检查
2. **检查标题选择器**：`document.querySelectorAll('input[type="text"]')`
3. **检查正文选择器**：`document.querySelectorAll('[contenteditable="true"]')`
4. **检查发布按钮**：`document.querySelectorAll('.button-dhlUZE.primary-cECiOJ')`
5. **测试模式**：先用 `testMode: true` 验证表单填写，再测真实发布
6. **复现崩溃**：手动操作看是否会崩溃 → 如果手动也崩溃，100% 是 Electron/Chromium 版本问题
