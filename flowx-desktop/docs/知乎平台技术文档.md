## 第三章 图文发布（image）

### 3.1 发布页 URL 与入口

**图文发布 URL**：`https://www.zhihu.com/creation/new-content`

知乎的创作中心统一入口，支持文章/想法/视频等多种内容形式的创建。

### 3.2 标准发布流程

```
1. 窗口初始化 + NavigationTracker
2. loadURL 创作发布页 + 导航稳定
3. detectLoggedIn + 未登录显示窗口等 120s
4. 填写标题（如有独立标题字段）
5. 填写正文（ProseMirror 富文本编辑器，核心难点）
6. 图片上传（如有）
7. 添加话题标签
8. 点击发布按钮
9. 成功信号轮询
10. 完成
```

### 3.3 页面结构总览

知乎图文发布页采用 **ProseMirror** 富文本编辑器，这是一个基于 contenteditable 的现代富文本编辑框架。

```html
<!-- 标题输入框 -->
<input type="text" placeholder="请输入标题" />

<!-- 正文编辑器（ProseMirror） -->
<div class="ProseMirror" contenteditable="true">
  <p>正文内容...</p>
</div>

<!-- 工具栏 -->
<div class="editor-toolbar">
  <button>加粗</button>
  <button>图片</button>
  ...
</div>

<!-- 发布按钮 -->
<button class="Button--primary">发布</button>
```

### 3.4 标题填写

知乎标题输入框为标准 input 元素，使用 execCommand 方式确保受控组件同步：
```javascript
input.focus();
document.execCommand('selectAll');
document.execCommand('delete');
document.execCommand('insertText', false, titleText);
```

### 3.5 正文填写（ProseMirror 富文本编辑器）

**核心难点**：ProseMirror 是一个基于 contenteditable 的富文本框架，直接设置 innerHTML 会破坏其内部 state。

**解决方案：document.execCommand + 逐行插入**

```javascript
// 定位 ProseMirror 编辑器
var target = document.querySelector('.ProseMirror');

// 聚焦并清空
target.focus();
document.execCommand('selectAll');
document.execCommand('delete');

// 逐行插入（保持段落结构）
var lines = fullText.split('\n');
for (var j = 0; j < lines.length; j++) {
  if (lines[j]) {
    document.execCommand('insertText', false, lines[j]);
  }
  if (j < lines.length - 1) {
    document.execCommand('insertText', false, '\n');
  }
}
```

**为什么 execCommand 能工作**：
1. `execCommand('insertText')` 触发原生 `input` 事件
2. ProseMirror 监听 input 事件，解析 DOM 变化并更新内部 state
3. 保证编辑器内部状态和 DOM 一致

### 3.6 图片上传技术方案

知乎图文发布的图片上传通过工具栏的「图片」按钮触发。

**上传方式**：
- FileChooser 拦截方案（优先）
- 定位隐藏 file input + DOM.setFileInputFiles（兜底）

**上传完成确认**：
- 等待编辑器内出现 `<img>` 标签
- 检查图片 URL 是否加载完成

### 3.7 话题标签

知乎的话题/标签通过专门的输入框添加，与正文分离。

### 3.8 发布按钮与结果检测

## 第五章 核心技术要点

### 5.1 ProseMirror 编辑器内容注入原理

ProseMirror 的核心设计是 **Model 驱动 View**：

```
用户输入 → DOM input 事件 → ProseMirror 解析 DOM → 
更新 State Model → 重新渲染 View → DOM 更新
```

**三种注入方式对比**：

| 方式 | 是否更新 ProseMirror state | 保存后是否保留 | 推荐度 |
|:---|:---:|:---:|:---:|
| 直接设置 innerHTML | ❌ 否 | ❌ 会被覆盖 | 不推荐 |
| dispatch Transaction（需 PM 实例） | ✅ 是 | ✅ 是 | 最正确但难获取实例 |
| **document.execCommand('insertText')** | ✅ 是（通过 input 事件） | ✅ 是 | **推荐** |

### 5.2 execCommand 的兼容性优势

尽管 `document.execCommand` 在规范中已被标记为 deprecated，但在实际自动化场景中具有不可替代的优势：

1. **原生事件触发**：自动触发 input、beforeinput、keydown 等事件
2. **编辑器兼容性**：几乎所有基于 contenteditable 的编辑器都兼容
3. **撤销栈支持**：操作会被加入编辑器的 undo/redo 历史
4. **无需内部 API**：不需要获取编辑器实例或内部 state

适用范围：ProseMirror、Quill、Slate、WangEditor、UEditor 等几乎所有富文本编辑器。

## 第六章 排错指南

| 失败现象 | 可能原因 | 排查方法 |
|:---|:---|:---|
| 正文填了但保存后消失 | 没用 execCommand，ProseMirror state 未更新 | 确认使用了 execCommand 方式 |
| 图片上传无响应 | FileChooser 未拦截成功 | 检查工具栏图片按钮的选择器 |
| 发布按钮找不到 | 按钮 disabled 或在不可见区域 | 检查按钮是否有 disabled 属性，是否需要滚动 |
| 登录后仍判未登录 | z_c0 cookie 未写入 | 检查 detectLoggedIn 日志的 cookie 列表 |
| 标题填了消失 | React 受控组件问题 | 确认使用了 execCommand 方式 |
