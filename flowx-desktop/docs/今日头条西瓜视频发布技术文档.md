# 今日头条西瓜视频发布技术文档

> 版本：v1.0 | 最后更新：2026-08-05
> 适配代码：`flowx-desktop/src/main/services/platforms/toutiao.ts` 的 `runXiguaVideoPublish`
> 发布页地址：`https://mp.toutiao.com/profile_v4/xigua/upload-video`

---

## 一、接入概览

今日头条的视频发布入口使用「西瓜创作平台」（`xigua_upload-video-wrapper`），与抖音创作平台 `creator.douyin.com/creator-micro/content/upload` 是同源技术栈（字节系 `xigua-upload-manage` 组件）。

### 1.1 支持的内容类型

| 类型 | 对应 `PublishRequest.contentType` | `capabilities` |
|:---|:---|:---:|
| 西瓜视频（头条视频） | `video` | ✅ `publishVideo: true` |
| 微头条图文 | `image` | ✅ `publishImage: true` |
| 图文长文（文章） | `article` | ❌ `publishArticle: false` |

### 1.2 相关常量（toutiao.ts）

- `XIGUA_VIDEO_PUBLISH_URL`: `https://mp.toutiao.com/profile_v4/xigua/upload-video`
- `XIGUA_VIDEO_TITLE_MIN = 5`：标题最少 5 字（不满足会自动追加「精彩内容」凑足）
- `XIGUA_VIDEO_TITLE_LIMIT = 30`：标题最多 30 字（超出后 `trimEnd() + …`）
- `XIGUA_VIDEO_ABSTRACT_LIMIT = 2000`：视频简介最多 2000 字

## 二、标准 10 步发布流程

`runXiguaVideoPublish(accountId, request, onProgress)` 严格按以下 10 步执行，每一步有明确的失败分支：

| 步骤 | 进度 | 说明 | 失败处理 |
|:---|:---:|:---|:---|
| 1 | 5 | 创建发布窗口，`makePublishWindow` 基于 `persist:account_{id}` 独立 session | - |
| 2 | 10 | `win.loadURL` 进入视频发布页，`tracker.waitForStable(1500, 15000)` 等待导航静默 + 1.8s 渲染缓冲 | - |
| 3 | 15-20 | `detectLoggedIn` 复用微头条登录检测（`sessionid / sid_tt` cookie + DOM 辅助）；未登录则显示窗口，每 3 秒轮询最多 120 秒；登录后回到发布页 | 超时 → `makeFailedResult("登录超时")` |
| 4 | 22 | 结构就绪校验：`buildProbeXiguaVideoPageScript()` 最多轮询 20s，要求 `wrapperFound || (anchorFound && fileInputs>0)`；未命中就 `buildCheckFileInputScript()` 找 `input[type=file]` fallback | 都不满足 → `视频发布页结构未就绪` |
| 5 | 25 | `uploadViaCDP(win, [videoFile], plog, 'video')` 注入视频文件（CDP `DOM.setFileInputFiles` + `Runtime.callFunctionOn` 派发 change/input） | 失败 → `视频文件上传失败（CDP注入未成功）` |
| 6 | 35-80 | `buildProbeXiguaVideoProgressScript()` 轮询上传/转码进度（每 4s 一次最多 10 分钟）；完成判定：`res.allDone = total>0 && finished>=total && error=0 && formReady`；未达 allDone 但 `formReady` 宽限通过 | `error>0` 立刻报错；10 分钟仍未 formReady 才判超时 |
| 7 | 80 | 填写标题：`buildFillXiguaVideoTitleScript(finalTitle)`；长度不足 5 字自动追加 ` 精彩内容`，超过 30 字截断+省略号；填写后检测 `afterVal.length>=5`，不满足最多再补一轮 | - |
| 8 | 80 | 填写简介（可选）：`request.content` 经 `truncate(content, 2000)` 后填到 `.form-item-abstract .abstract` | - |
| 9 | 90 | 发布按钮：每 1.2s 一轮共 3 轮；轮前 `buildProbeXiguaVideoPageScript` 检测 `publishBtn.disabled`（Disabled 就等 1.5s 跳过本轮）；`buildClickXiguaVideoPublishScript()` 以「footer 作用域加权评分」命中最像发布按钮的元素点击 | 3 轮都没点中 → `视频发布按钮点击失败` |
| 10 | 95-100 | 发布结果轮询（每 2.5s 最多 120s）：`buildPublishResultProbeScript()` → 关键词/Toast/URL 跳转；未命中但 `URL 已离开 upload-video && 无 failReason` 宽松判成功；否则 2 分钟超时 | 最终未成功 → `failReason 或 视频发布结果确认超时` |

### 2.1 PublishRequest 入参到表单字段映射

| PublishRequest 字段 | 目标表单字段 | 说明 |
|:---|:---|:---|
| `mediaFiles[0]` | `.m-upload-anchor .byte-upload-trigger input[type=file]` | 第一个文件作为视频源 |
| `title`（不足 5 字补齐 ` 精彩内容`，最长 30 字） | `.form-item-title .video-form-item-control textarea`（3 层定位兜底） | 必填 |
| `content`（最长 2000 字） | `.form-item-abstract .abstract / .form-item-sub-title` | 可选（简介/描述） |
| `tags` | ❌（暂未接入） | 视频话题后续扩展 |
| `coverImage` | ❌（暂未接入，使用西瓜默认抽取封面） | 后续可扩展 `.form-item-poster` |

## 三、关键技术细节

### 3.1 上传/转码就绪的 3 阶段判定

西瓜视频发布不是「传完文件马上就能点发布」，必须经历 3 个阶段，脚本逐项检测：

```
  注入 CDP 文件
      │
      ▼
 ┌─────────────┐     ┌─────────────┐     ┌──────────────────────────┐
 │  uploading  │ ──▶ │  scanning   │ ──▶ │  finish + formReady    │
 │  (上传中)    │     │  (转码中)    │     │  (上传完成 + 表单渲染) │
 └─────────────┘     └─────────────┘     └──────────────────────────┘
process-item-icon 类名依次切换：.uploading → .scanning → .finish
```

脚本 `buildProbeXiguaVideoProgressScript` 的 `allDone` 判定：

```js
res.allDone = (
  res.total > 0          // 至少出现 1 条 progress-item（表示已真正开始处理，不是注入后还未接收）
  &&
  res.finished >= res.total  // 所有进度项达到 finish
  &&
  res.error === 0           // 没有 error 类名
  &&
  res.formReady             // DOM 里已经有 .video-form-basic + .form-item-title（说明西瓜后台处理完，进入填写信息阶段）
)
```

#### 宽限规则
实际生产中偶尔会卡在 `scanning`（1% 进度条不更新）但表单已经渲染出来（用户手动可以继续操作）。为避免这种「视觉上明明可以填标题但脚本死等 finish」的假超时，提供宽限：

```ts
if (!allDone) {
  if (lastProgressInfo && lastProgressInfo.formReady) {
    plog('info', 'progress', '表单已渲染，宽限继续（即使 progress 未达 100%）');
  } else {
    return makeFailedResult(..., '视频上传/转码超时或表单未渲染（10分钟）');
  }
}
```

### 3.2 标题填写三层兜底

真实 DOM 里标题字段可能出现 3 种形式（不同西瓜版本/AB 实验），脚本依次尝试：

| 优先级 | 定位方式 | 示例类名路径 |
|:---|:---|:---|
| 1（精确） | `.form-item-title .video-form-item-control > textarea / [contenteditable]` | 符合 video-form-bone 规范结构 |
| 2（表单内） | `.video-form-basic textarea` 第一个 placeholder 含「标题/title」的 | 结构变动时兜底 |
| 3（全局） | `document.querySelectorAll('textarea')` 中第一个 placeholder 含「标题」的 | 极端 fallback |

填完后强制 `dispatchEvent` 3 个事件：`input`、`change`、`blur`，保证 React/Vue 受控组件的双向绑定能同步更新到 state（否则发布按钮会一直 disabled，校验不通过）。

### 3.3 发布按钮 footer 作用域加权

`buildClickXiguaVideoPublishScript` 用评分避免误点到页面其他位置的「发布」（如左侧导航残留元素、弹窗），加权规则：

| 判定项 | 加/减分 |
|:---|---:|
| 父链（最多向上 8 层）命中 `.publish-footer` / `.video-batch` / `.footer-content` | **+200**（权重最大） |
| 元素 class 含 `publish` / `publish-btn` | +80 |
| class 含 `primary` | +50 |
| class 含 `byte-btn` | +30 |
| 文本完全匹配「发布」/「立即发布」/「确认发布」 | +100~80（按优先级） |
| `offsetWidth / offsetHeight = 0`（不可见） | 直接淘汰 |
| `disabled / aria-disabled=true` | **-1000**（直接扔出候选池） |

并通过 `parentElement.closest` 向上追溯 8 层来识别作用域 —— 这个设计参考了微信视频号 `Shadow+Iframe` 的点击作用域判定，避免跨层误点。

### 3.4 发布结果成功的宽松判定

- **强命中（立即通过）**：`body 文本` 命中「发布成功/已发布/已发布，正在审核/发布完成/微头条已发布」，或 URL 含 `success=true / published=true`，或 toast/notification/message 元素内命中成功关键词。
- **弱命中（120s 结束时兜底）**：如果按钮点击后 URL 已经从 `xigua/upload-video` 跳走，且 `hitFail.length === 0`，也当作成功。这是为了兼容发布后立即跳内容管理页但没弹 toast 的场景。

### 5.2 常见错误 & 排查方向

| 错误提示 | 根因猜测 | 排查建议 |
|:---|:---|:---|
| 视频发布缺少 mediaFiles | 调用方没传视频文件 | 检查 PublishRequest.mediaFiles 是否非空数组 |
| 登录超时 | 浏览器 session 过期 / 扫码后未跳转 profile_v4 | 手动在账号管理里重新「刷新账号」，或延长等待时长 |
| 视频发布页结构未就绪（未找到上传锚点或文件输入） | 页面仍在 SSR 渲染 / 西瓜发布改版 | 打开 `profile_v4/xigua/upload-video` 截图看是否有 `上传视频` 按钮；用 DevTools 搜 `upload-video-trigger-btn` |
| 视频上传/转码出错 (progress.error=N) | 文件被损坏 / 码率过高被拒 / 网络波动 | 看 bodyTip 里有没有「视频格式不支持/请检查视频完整性」字样；换个正常文件重测 |
| 视频上传/转码超时或表单未渲染（10分钟） | 文件超大（>2GB）+ 码率高，或 10 分钟都没等到 formReady | 调大 `upTimeout` 或手动确认是否真的还在转码 |
| 视频发布按钮点击失败（3 次重试均未匹配） | 按钮 disabled 或西瓜改版换了类名 | 每轮执行前 log 会打 `probe-before-publish` publishBtn.disabled / cls / topThree；对比最新 DOM 是否把 `.publish-footer` 改名为其他 |
| 视频发布结果确认超时（2 分钟未检测到发布成功/跳转变更） | 发布后没跳转也没弹 toast（西瓜改版） | 在浏览器手动点一次发布，看结果页 URL 是否真的含 success / 有没有新 Toast 样式；如果只是样式改了补关键词到 `successKeywords` |

## 六、踩坑汇总 & 禁止事项

1. **❌ 禁止用 `videoFile` 自定义字段取文件。** `PublishRequest` 接口统一只有 `mediaFiles: string[]`（`contentType=video` 时 mediaFiles[0] 就是视频）。任何时候直接读 `.videoFile` 会被 TypeScript 打红。
2. **❌ 禁止 `evalJS` 调 3 个参数。** shared.ts 的签名是 `evalJS(win, code, desc, log, opts?)`，必须带第 4 参数 `plog`（否则编译直接 `TS2554 Expected 4-5 arguments, but got 3`）。
3. **❌ 禁止 `PublishItemProgress` 乱塞 `contentType / title / url` 字段。** 正确字段名是 `progress (0-100) / message / resultUrl / startedAt / finishedAt`，和 `makeFailedResult` 保持一致。
4. **❌ 禁止 inject 文件后立刻就去填标题。** 必须等 `formReady=true`；西瓜在转码完成前根本不渲染 `.video-form-basic`，你去选 textarea 只会是 `null`。
5. **❌ 禁止用 `document.execCommand` 填标题。** 字节系 `byte-textarea-wrapper` 受控组件只认 `target.value + dispatchEvent('input')`；execCommand 会写到 DOM 上但状态不更新，发布按钮一直 disabled。
6. **✅ 建议：标题一定要 ≥5 字。** 西瓜后台发布校验最少 5 字，否则前端会出 m-error-tips，按钮 disabled。`runXiguaVideoPublish` 已内置自动补「 精彩内容」，但业务层如果能保证 5+ 字优先传完整标题。
7. **✅ 建议：先验证测试模式（testMode=true）。** 正式发布前先用 testMode 跑一遍：窗口保持打开，可以肉眼确认标题、简介是否被正确填入，发布按钮的 topThree 评分是否命中预期元素，避免直接发错内容。
