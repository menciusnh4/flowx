## 一、目标页面结构分析

### 1.1 发布页 URL（两套）

| 内容类型 | URL | 说明 |
|:---|:---|:---|
| 视频发布 | `https://weibo.com/upload/channel` | 独立的视频上传与表单填写页（非创作中心） |
| 图文 / 纯文本发布 | `https://weibo.com/`（首页顶部发布卡片） | 位于首页顶部的发布表单（publishCard），**没有独立标题字段**，标题和正文拼接写入同一个 textarea |

> **重要**：视频发布和图文发布不在同一个 URL、甚至不在同一组 DOM。两者分别走独立的发布函数（`runWeiboPublish` 视频 / `runWeiboPublishImage` 图文），共享同一套「登录检测 + 填写脚本工具 + CDP 调试器工具 + 测试探针 + 成功信号轮询」。

### 1.4 关键发现（决定实现策略）

1. **图文页没有独立标题字段**：首页只有 `textarea._input_1rz8r_8`，必须「title 换行 content 换行 tags」；视频发布页有独立标题 `填写标题（0～30个字）` + 独立正文 textarea（内容不再重复带标题）
2. **所有真实隐藏 input 外层有多层 `display:none`**：图文和视频都是「宽 50% 的 div + display:none」包裹着 `input._file_hqmwy_20`；
   - ❌ **禁止**：任何解除父级 `style="display:none"` 的脚本（会把 WooDivider、自定义分类下拉、分隔线变成 block，页面完全乱）
   - ✅ **正确**：直接用 `DOM.setFileInputFiles` 注入到**真实隐藏的 input 本体**，或走 `Page.setInterceptFileChooserDialog + 点击图片/视频按钮` 两条路
3. **上传成功判定必须以组件渲染出缩略图为准**：方案 B（临时 input + drop）只会让我们代码内部的 count 变成 2，但微博 uploader 内部 onChange 实际未触发；最终判真必须等 `._box2_vkpry_14` 下 `._pic_1syq3_2 img.woo-picture-img` 数量 ≥ 期望数量且带 `_close_1syq3_42` 删除按钮
4. **视频发布封面等待**：上传成功后还需要异步抽取 10 张候选封面（`_a5rt_1gx9k_237` 容器），未抽齐时点发布会被禁用 → 需要专门阶段轮询
5. **发送/发布按钮 disabled 控制严格**：字数超限、图片/封面未就绪、分类未选都会导致按钮 disabled；代码里要先返回清晰错误原因
6. **CSS class 是构建 hash（`_1ishf_14 / _6c8b7_2 / _1rz8r_8 / _1jg7d_67 / _2z30i_68 / _1syq3_2 / _1gx9k_237`）**：每周一次打包更新，主选择器必须同时提供 hash 精确命中 + placeholder/文本语义兜底，避免线上换版失效

## 二、完整发布流程

### 2.1 工厂方法 + 适配器调用链

```
PublishEngine.submit(req)
  └─> PlatformDispatcher.createExecutor('weibo', contentType)
        └─> weibo.ts 适配器分发
              contentType === 'video'   -> publishVideo() -> runWeiboPublish(..., 'video')
              contentType === 'image'   -> publishImage() -> runWeiboPublishImage()
              contentType === 'article' -> publishArticle() -> makeFailedResult('待实现')
```

### 2.2 图文/纯文本发布流程（`runWeiboPublishImage`）

共 8 步，总生命周期 ~ 60~180s（取决于图片张数）：

```
1. 窗口 + NavigationTracker
     makePublishWindow(accountId, title)
     attachNavigationTracker(win, log)   → waitForStable(1.5s)

2. 加载 https://weibo.com/ 首页
     detectLoggedIn(win)
       ├─ 已登录 -> 走第 3 步
       └─ 未登录 -> 显示窗口 + 120s 等待用户手动登录后重加载首页

3. 组装正文：title(≤30) + '\n' + content + '\n' + tags
     总长 ≤ 2000 字；tags 用 prepareTags → #话题# 拼接

4. 上传图片（有 mediaFiles 时）
     uploadWeiboImage(win, imageFiles, log):
       ├─ 方案 A：Page.setInterceptFileChooserDialog + 点击「图片」入口
       │   └─ handleFileChooser(action:'accept', files)
       └─ 方案 C（兜底）：定位真实隐藏 input._file_hqmwy_20
           ├─ DOM.getDocument(pierce:true)
           ├─ DOM.querySelectorAll → DOM.resolveNode 拿 objectId
           ├─ DOM.setFileInputFiles({objectId, files})
           └─ 在该 input 本体上 dispatch: focus → input → change → blur
     最终校验（45s 轮询，每 2.5s 一次）：
       ._box2_vkpry_14
         ├─ :scope > div 非 display:none (innerHidden=false)
         ├─ ._picbed_1syq3_2 下 img.woo-picture-img:
         │    src ∈ wx*.sinaimg.cn / tvax*.sinaimg.cn, count >= 期望数量
         └─ 每张都有 _close_1syq3_42 删除按钮

5. 填写正文（buildFillContentScript）
     精确匹配 textarea._input_1rz8r_8
       placeholder="有什么新鲜事想分享给大家？"
       使用 native setter（React.valueTracker 兼容）+ input/change/blur

6. 测试模式 / 正式发布
     测试模式：buildTestModeProbeScript(
       buttons=[._btn_2z30i_, ._check_2z30i_81>button, woo-button-primary],
       fields =[微博正文 textarea]
     ) + 补一层 getComputedStyle 可见性兜底（offsetParent===null 场景）
     正式发布：
       优先 button[._btn_2z30i_] / ._check_2z30i_81>button;
       回退：文本「发送/发布」+ 排除黑名单（再发一条/表情/视频/话题/更多/定时/公开）

7. 成功信号轮询（180s，每 3s 一次）
     ├─ URL 变化：脱离首页 URL 或命中 /status|profile|mblog|publishSuccess/
     └─ bodyText 命中：发布成功|发送成功|发布完成|已发送|发送完成|发博成功|成功发布
     失败关键词：发布失败|不符合|违规|字数超限|未通过|请先登录|登录状态已失效

8. finally：
     - 测试模式：setupTestModeWindow 接管（不关窗）
     - 正式模式：setTimeout 4s 后关窗
```

## 三、核心难点与解决方案

### 难点 1：视频 + 图文 两个 URL 的登录态判定相互误判

**问题**：视频发布页 `weibo.com/upload/channel` 不在原先的创作中心（`me.weibo.com`）白名单里，DOM 也不匹配「个人 tab / 创作中心头像」两套结构，导致误判「未登录」。

**解决方案**：在 `detectLoggedIn` 中新增：
```typescript
const inUploadPage = currentUrl.includes('weibo.com/upload/');
const inBackend =
  currentUrl.includes('me.weibo.com') ||
  currentUrl.includes('weibo.com/u/') ||
  currentUrl.includes('weibo.com/p/') ||
  inUploadPage;  // 新增

// 登录态：SUB cookie + 非登录页 + (inBackend OR 结构识别)
```

同时在「视频流程未登录场景」下显示窗口让用户手动登录，登录成功后重新导航回 `upload/channel`（避免默认回到首页）。

**相关日志标记**：`matchedKeywords: 'in-upload-page'`

### 难点 2：真实隐藏 input 有多层 display:none，强制解除会破坏布局

**问题**：旧方案 B（临时 input + drop）根本没触碰到真实 `input._file_hqmwy_20` 所关联的 uploader，导致「代码内部 count=2 但页面完全没显示图片」的假成功。

**解决方案（两条严格红线）**：
1. **绝不解除 display:none**：任何解除的操作会把 WooDivider 撑破、把自定义分类下拉收起态永久展开、把完成层 `_layer1_9a8j7_2` 一直显示遮挡表单
2. **直接注入到真实隐藏 input 本体**：
   ```typescript
   // 1) 精确定位真实隐藏 input
   const selectors = ['input._file_hqmwy_20', 'input[class*="_file_hqmwy_"]', 'input[accept*="image/*"]'];
   // DOM.getDocument → DOM.querySelectorAll → DOM.resolveNode → objectId
   // 2) 注入
   DOM.setFileInputFiles({ objectId, files })
   // 3) 只在该 input 本体上触发 focus→input→change→blur
   ```
3. **上传成功必须用组件自己的渲染结果（缩略图）判真**：见 §3.3

### 难点 3：FileChooser 在 Electron 中 handleFileChooser 偶尔失败（No node with given id / params 缺 frameId）

**问题**：某些 Electron/Chromium 版本要求回传时必须带 `frameId` + `backendNodeId`（从 `fileChooserOpened` 事件带回的 params）。

**解决方案**（方案 A 里）：
```typescript
const cmdArgs = { action: 'accept', files: imageFiles } as any;
if (params.frameId)       cmdArgs.frameId       = params.frameId;
if (params.backendNodeId) cmdArgs.backendNodeId = params.backendNodeId;
await sendCommand('Page.handleFileChooser', cmdArgs);
```

加上超时时长从 12s → 18s（图片图标展开有 pop-over 延迟），并在失败时立刻降级到「方案 C：直接注入真实隐藏 input」。

### 难点 4：视频发布必须等封面生成

**问题**：上传完成但视频解码未完成时，`._a5rt_1gx9k_237` 里的 10 张候选图仍不存在，发布按钮会被平台自己置为 disabled，自动化点击失败。

**解决方案（步骤 6.5：等待封面生成）**：
每 2s 扫描，最长 2 分钟：
- 容器：`_a5rt_1gx9k_237` / `_a5list_1gx9k_304`
- 有效 img：`src` 非空、非 about/data/`"false"`、必须匹配 `wx*.sinaimg.cn` / `tvax*.sinaimg.cn`
- 已选图：优先 `_a5itemcurr_1gx9k_367` 的第一张，兜底取第一张有效

```
[weibo][upload] 封面尚未生成: {"ready":false,"reason":"no-valid-imgs","count":0}，继续等待…(剩余 118s)
[weibo][upload] ✅ 封面已就绪: 共 10 张候选，已选=https://wx2.sinaimg.cn/large/...
```

**超时策略**：2 分钟仍未就绪时**不直接失败**，继续填写表单。因为有些宽松校验场景下封面可以发布后补；但如果最终发布按钮 disabled，失败原因会在第 8 步清晰返回。

### 难点 5：发布按钮被 offsetParent 检测误判为不可见（fixed/absolute 容器场景）

**问题**：`shared.ts` 的 buildTestModeProbeScript 用「`offsetParent !== null`」判定可见，在微博按钮（`_check_2z30i_81` 位于 fixed/absolute 父级容器里）时 offsetParent 恒等于 `null` → 即使 DOM 有按钮也判定未找到。

**解决方案**：在 weibo.ts 每次探针返回后，**再补一层兜底扫描**：
```javascript
getComputedStyle(el).display  !== 'none' &&
getComputedStyle(el).visibility !== 'hidden' &&
getBoundingClientRect().width > 1 && height > 1
```
命中时把 `publishButtonFound=true`、`note: '探针脚本兜底找到发布按钮'`、写入 rect（测试模式高亮）。

## 五、排错指南（Troubleshooting）

### 5.1 登录 & 授权相关

| 现象 | 可能原因 | 排查 |
|:---|:---|:---|
| 「upload/channel 明明已登录仍判未登录」 | 旧版白名单漏了 `weibo.com/upload` | 看 `detectLoggedIn` 返回的 `matchedKeywords` 是否含 `in-upload-page`（v1.0+ 已加） |
| 首页图文发布提示「登录超时」 | session partition 不同步 / 用户 120s 未扫码 | 调大 `runWeiboPublishImage` 登录等待上限；或手动打开窗口 10 分钟内扫码 |

### 5.2 图文图片上传相关

| 现象 | 可能原因 | 排查方法 |
|:---|:---|:---|
| ✅ [C] drop 完成 → 但没图片 | 旧方案 B 的假成功（已废弃） | 看日志 45s 内「缩略图校验中」的 validImgs，应该 ≥ 期望才返回 true |
| FileChooser 失败 → handleFileChooser 报错 `No node with given id` | 老 Electron CDP 要 frameId + backendNodeId | 看 log 的 `params=...`，v1.0 已把两个 param 带回 |
| 45s 仍没有缩略图（validImgs=0） | 真实隐藏 input 被选错：不是 `_file_hqmwy_20`，或注入到视频页了 | 看 `[C] 定位 input: {...}` 日志中 nodes 的 class/accept，确认命中了 `accept="image/*...video/*..."` 的那个 input |
| 图片有了但「发送」按钮 disabled | 正文 textarea 仍空 / 上传中 / 平台风控提示 | 运行时在控制台打 `$0.disabled` 看按钮，再看页面有无「请完成 xxx」的红色提示文字 |

### 5.3 视频上传相关

| 现象 | 可能原因 | 排查 |
|:---|:---|:---|
| 分类/封面未就绪就写标题导致发布按钮 disabled | 顺序不对（标题→分类→封面必须按平台受控顺序填） | v1.0 表单顺序已经固定：原创 → 标题 → 分类 → 正文 |
| 正文显示出 2 次「一键开天」 | 旧版 buildWeiboText(skipTitle=false) 把标题也写入了正文 | v1.0 正文只拼 content + tags，若仍有则需要检查 testResult 中正文 value 是否包含标题 |
| 测试模式 publishButtonFound=false 但实际页面按钮存在 | offsetParent 兜底脚本未命中 / button class 新 hash | 把新 button class 字符串发给作者，补充 exact selector |
