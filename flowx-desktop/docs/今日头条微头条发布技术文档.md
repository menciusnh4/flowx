## 二、账号接入完整流程

### 2.1 授权流程（AccountService.beginAuthorization）

```
新增账号 → 选择「今日头条」
     ↓
打开 BrowserWindow partition=persist:account_{id}
loadURL(mp.toutiao.com/profile_v4/index)
     ↓
page-title-updated + did-navigate-in-page + 500ms 轮询 detectLoggedIn
     ↓ (扫码/手机号登录成功后，URL 进入 profile_v4/index)
detectLoggedIn.loggedIn=true → 立即 extractPageInfo
     ↓
昵称 / 头像 / 头条号ID / 粉丝数 → 写入 SecureStore（加密保存）
```

授权入口：
- 浏览器会展示「扫码登录」或「账号密码登录」
- 成功后自动跳转到创作中心首页（`profile_v4/index`）

### 2.2 detectLoggedIn — 登录态检测（4 重判断）

**签名**：`async detectLoggedIn(win) → { loggedIn, url, title, matchedKeywords }`

```ts
// 第 1 重：核心 cookie（两者有其一即可）
cookies.sessionid    ← 头条登录后必存在的会话
cookies.sid_tt       ← 另一种兼容形式的会话 cookie

// 第 2 重：URL 排除法
isLoginPage = url.includes('/auth/page/login') || (url.includes('login') && !url.includes('profile'))
// → 只要在登录页肯定未登录

// 第 3 重：URL 正增强
inBackend = url.includes('profile_v4') || url.includes('/creator/')
// → 已进入创作中心后端

// 第 4 重：DOM 辅助（cookie 被刷新时兜底）
nickname DOM: .nickname / .user-name / [class*="nickname"]
body 文本：出现「退出登录」 + 「内容管理 / 数据分析」同时成立

// 最终判定：
loggedIn = (!!sessionid || !!sid_tt) && !isLoginPage
```

**返回字段说明**：
| 字段 | 说明 |
|:---|:---|
| `matchedKeywords` | 命中的判断路径，例如 `["sessionid-cookie", "in-backend", "dom-profile"]`，便于排查登录判断失效时具体哪一层出问题 |
| `loggedIn=false` 但有 cookie | 通常说明 URL 被重定向到了「登录失效 → 重新登录」过渡页，再等 3s 轮询一次即可 |

**应用在发布流程里的登录等待逻辑（视频/图文通用）**：
- 最多 120s，每 3s 轮询一次 detectLoggedIn
- 未登录时 `win.show()` + `win.focus()`，强制把账号窗口前置让用户操作
- 登录后若不在对应发布页，则重新 `loadURL(目标发布页)`

### 2.3 extractPageInfo — 信息提取（昵称 / 头像 / 头条号ID / 粉丝数）

```ts
// ① 昵称：多层选择器兜底 + 过滤占位词
.auth-avator-name → .user-panel .auth-avator-name → .nickname → .user-name → [class*="nickname"]
过滤（必须满足：长度<50，且不是「头条号 / 下午好 / 上午好 / 晚上好 / 欢迎」）
兜底：.menu-title 正则 /[，,]\s*(.+)$/  （「创作中心，我的头条号」格式）

// ② 头像：
.auth-avator-img → .user-panel .auth-avator-img → [class*="auth-avator"] img → .avatar img → [class*="avatar"] img
过滤：跳过 data: URI（占位图）

// ③ 平台账号ID（头条号纯数字 ID）：
所有 a[href*="/c/user/"] 链接正则 /\/c\/user\/(\d+)/

// ④ 粉丝数：.data-board-item 第 1 张卡片
.data-board-item → .data-board-item-primary 文本
支持 1.2万 → *10000 转整数
```

**账号去重规则**：`platform='toutiao' + platformAccountId（头条号数字ID）` 完全相同视为同一账号，刷新会覆盖旧记录，而不是新增。

### 2.4 健康检测 / 刷新账号 / 打开创作中心

| 操作 | 行为 |
|:---|:---|
| **刷新账号** | 在旧 partition 中重新 `loadURL(homeUrl)` → 等稳定 → detectLoggedIn → extractPageInfo → 覆盖保存 SecureStore |
| **打开创作中心** | 新 BrowserWindow 独立 partition 注入 account cookies → loadURL(homeUrl) |
| **健康检测** | 每 7 天或手动触发：loadURL(homeUrl) → waitForStable → detectLoggedIn；失败状态置为 expired |
| **删除账号** | SecureStore 移除记录 + 删本地头像文件（`cleanupOldAvatarsFor`） |

| 6 | 30 | CDP uploadViaCDP 注入图片到抽屉 input[type=file] | 失败 → `图片上传失败（CDP注入未成功）` |

| 9 | 70 | 点击抽屉「确定」（最多 3 次，优先 data-e2e=imageUploadConfirm-btn） | 3 次失败 → `抽屉确定点击失败` |
| 10 | 75 | 抽屉关闭等待 + div.upload-list 预览缩略图区 background-image URL 去重（最多 2 轮） | - |
| 11 | 80 | 填写正文（ProseMirror）：零宽字符/换行清理 + 最多 2000 字截断 | - |
| 12 | 85 | 逐个输入话题 `#tag`（CDP 真实键盘）→ 浮层稳定匹配 → 不匹配按 **1 次 Space 取消** | 话题不匹配不算失败，仅 skipped |
| 13 | 90-95 | 测试模式 probe（高亮发布按钮）或正式 clickPublish | - |

### 3.3 草稿撤销弹窗 + 残留图片清理

**点击时机**：页面加载后立即最多 33 轮轮询。为什么必须先撤？—— 草稿会自动把上一次未发布的图片 + 正文回显到编辑器，不撤的话会与本次上传的图片混在一起，导致话题输入错位。

**撤销后清理顺序（buildClearDanglingImagesScript）**：
1. 编辑器 ProseMirror 内的 `img` / `figure`（removeChild 即可，ProseMirror 此时没在编辑态，Vue 不管理）
2. 抽屉内 `.pic-select-image-item-wrap .success` li 点 `.image-item-remove`（组件自己的删除逻辑）
3. `div.upload-list .img-box-item` 点 `i.image-remove-btn`

### 3.4 话题浮层推荐稳定匹配（核心难点）

**为什么必须「连续 2 轮 firstItemText 完全一致」才算 ready？**

字节的话题接口是「异步 ajax + IME 未提交字符 + ProseMirror composition 状态」三重叠加。输入 `#硅谷` 时第 1 轮只返回半截字 `#硅 252讨论`，直接点就错了；必须第 2 轮完全稳定才认为接口返回完整。

**不匹配的处理（只按 1 次 Space，不按 ESC、不删文本）**：

| 方案 | 副作用 | 说明 |
|:---|:---:|:---|
| ✅ 按 1 次 Space | **无** | 官方提示文案「敲空格可取消插入话题」，语义完全正确 |
| ❌ 按 ESC | **有** | ProseMirror ESC 会回退上一个 Mention token，导致前一个正确插入的话题也被撤销 |
| ❌ 连按 2 次 Space | **有** | 第二次 Space 在部分版本也有 cancel 副作用 |
| ❌ JS scrub 改 nodeValue | **有** | ProseMirror 复杂嵌套节点会导致 selection 错位，极端情况清空整个正文 |

**话题匹配分级（firstItemText → normalized vs tagName）**：

```
原始: "#硅谷# 1,394讨论"
  ① 去所有 # / ＃
  ② 去末尾 "数字 + 讨论/人/条/个/篇/阅读/万/亿/k/K/M/G"
  → normalized = "硅谷"

强匹配:   normalized === tagName                                    → 直接点选
前向匹配: normalized.startsWith(tagName) 且 next 字符不是字       → 点选（如 #AI → 候选「AI/ML 研究」 → 允许）
不匹配:   上面都不满足                                             → 按 1 次 Space 取消
```

### 3.5 图片重复三道防线

| 防线 | 触发时机 | 清理对象 | 核心约束 |
|:---:|:---|:---|:---|
| 1 | 撤销弹窗点击成功后立即执行 | 编辑器 img/figure + 抽屉 li + 预览区全局 | 编辑器可直接 removeChild（ProseMirror 已被撤销，不受 Vue 控制） |
| 2 | 抽屉 ready 后，点确定之前 | `li.pic-select-image-item-wrap.success` | **只点 `.image-item-remove`**；绝不能 removeChild → 会导致 v-for key 错 → 整个 footer 一起卸载 → 确定按钮消失 |

## 四、西瓜视频发布（`xigua/upload-video` + contentType=video）

发布入口：`runXiguaVideoPublish(accountId, request, onProgress)`

### 4.1 页面结构总览 — 横版 vs 竖版（**核心差异**）

根据上传视频的宽高比，`video-form-basic` 根节点会自动加 `.small-video` 类名，表示「竖版小视频」，其结构与横版（标准版）差别非常大：

```
video-from-container
└── .video-form-bone.video-form-basic  (标准版横版)
     OR  .video-form-bone.video-form-basic.small-video  (竖版)
        ├── .form-item-title  ← 标题（两版都存在）
        │
        ├── .form-item-poster  ← 封面（差异最大）
        │    横版:
        │      .xigua-poster-editor > .fake-upload-trigger (未上传点这里弹上传)
        │      .xigua-poster-editor > img  (已上传时显示 <img src="...")
        │
        │    竖版 small-video:
        │      .xigua-poster-editor.portrait
        │        ├── .bg [style=background-image:url("blob:https://mp.toutiao.com/xxx")]   ← ★ 封面真实存储位置（不是 <img>）
        │        └── .xigua-image-modify.portrait
        │               .image-modify-btn「编辑」  .image-modify-btn「替换」    ← ★ 要点「替换」弹上传，不再是 fakeUploadTrigger
        │
        ├── .form-item-abstract  ← 简介（横版可能有，竖版 small-video 可能没有）
        ├── .form-item-tags      ← 话题（横版可能有，竖版 small-video 可能没有）
        ├── .form-item-video2art ← 视频生成图文（checkbox）
        └── .form-item-source    ← 作品声明（checkbox 多选项：取自站外/引用站内/自行拍摄/AI生成/虚构演绎/投资观点/健康医疗）
```

**为什么竖版没有简介和话题？**—— 这是头条产品策略故意砍掉的，small-video 只需要标题 + 封面即可发布，脚本如果填了简介/话题也找不到对应 DOM，会直接以 `targetFound=false / filled=false` 返回（**不是失败**，只是跳过）。

### 4.2 标准 10 步发布流程（两版通用）

| Step | 进度 | 动作 | 竖版 small-video 差异 |
|:---|:---:|:---|:---|
| 1 | 5 | 分区创建发布窗口 | 无差异 |

### 4.4 竖版封面适配详解

#### 问题 A：竖版 hasImage 永远 false

**为什么**：竖版封面存储在 `div.bg` 的 CSS background-image 里（blob URL），不是 `<img src>`。旧代码只查 `ed.querySelectorAll('img')`，永远没结果。

**修复脚本（buildProbeXiguaVideoPosterScript 中）**：

```js
// 横版 img 逻辑之后 → 追加 portrait 解析：
if (!res.hasImage) {
  const bgDivs = ed.querySelectorAll
    ? ed.querySelectorAll('.bg, [class*="bg"], [style*="background-image"]')
    : [];
  for (let bi = 0; bi < bgDivs.length; bi++) {
    const d = bgDivs[bi];
    const styleStr = String(
      (d.currentStyle && d.currentStyle.backgroundImage) ||
      (d.style && d.style.backgroundImage) ||
      (d.getAttribute && d.getAttribute('style')) || ''
    );
    const bgMatch = styleStr.match(
      /url\(\s*['"]?\s*(blob:[^'")\s]+|https?:[^'")\s]+|data:[^'")\s]+)/i
    );
    if (bgMatch && bgMatch[1]) {
      res.hasImage = true;
      res.imageSrc = String(bgMatch[1]).slice(0, 200);
      res.diag.portraitBgStyle = styleStr.slice(0, 200);
      break;
    }
  }
}
```

#### 问题 B：竖版点错入口（点 fakeUploadTrigger）

**修复（buildOpenXiguaPosterDialogScript 中 coverEntry 分支）**：
- **优先**查找 `.xigua-image-modify .image-modify-btn` 文本匹配「替换」优先点选（返回）
- 只有没找到 portrait 替换按钮才 fallback fakeUploadTrigger

#### 问题 C：点确定后 confirmText 变「上传中」，脚本没等上传完就退出

**修复（cp 循环末尾新增独立上传中轮询段）**：
```
38 次 × 800ms ≈ 30s 等待
每次 probe:
  anyVisible=false      → 完成（弹窗关闭）
  dialogFinal.visible+hasOk → 完成（二次确认弹窗来了，说明上传已结束）
  dialog2.confirmText 重新匹配「非上传中」 → 完成
```

## 七、踩坑汇总 & 禁止事项

### 7.1 通用禁止

1. **❌ 禁止 PublishRequest 自定义字段取 `videoFile / posterFile`**。统一使用 `mediaFiles: string[]`（video 时 mediaFiles[0] 就是视频；封面使用独立 `coverImage` 字段）。
2. **❌ 禁止 `evalJS(win, code, desc)` 三参数调用**。必须严格签名：`evalJS(win, code, desc, log, opts?)`，最后一项 log 是必填，否则 TS2554。
3. **❌ 禁止 inject 文件后立刻去填标题 / 封面 / 简介等**。视频必须等 `formReady=true`；西瓜在转码完成前不渲染 `.video-form-basic`。
4. **❌ 禁止用 `document.execCommand` 填标题 / 简介**。字节 `byte-textarea-wrapper` / `xigua-input-wrapper` 只接受 `target.value setter + dispatchEvent('input' + 'change' + 'blur')`；execCommand 会写到 DOM 但 state 不更新 → 发布按钮永远 disabled。
5. **✅ 强烈建议每次改动先用测试模式跑一遍（testMode=true）**。测试模式高亮发布按钮 + 窗口保持打开，可以肉眼检查标题、封面是否正确写入，避免真发布错误内容。

### 7.2 图文微头条专属禁止

1. **❌ 禁止任何地方对抽屉内部 `li.pic-select-image-item-wrap` 使用 `removeChild`**。会破坏 v-for key → 整段 footer 卸载 → 确定按钮消失。
2. **❌ 禁止 div.upload-list 选择器放宽**。必须严格 `div.upload-list > div.img-box-item`，`div.upload-handler` 永远不匹配。
3. **❌ 话题匹配失败禁止按 ESC / scrub 文本 / 连按 2 次 Space**。必须只按 1 次 Space。

### 7.3 视频封面专属禁止

1. **❌ 竖版 small-video 禁止优先点 fakeUploadTrigger**。必须先找 `.xigua-image-modify.portrait .image-modify-btn` 文本匹配「替换」。
2. **❌ confirmText=「上传中」禁止继续点下一次确定**。必须进入 30s 独立轮询等待上传完成。
3. **❌ 封面 Dialog 的 DOM scope 只查 .Dialog-container 禁止只查单一选择器**。不满足就 Fallback-B DOM.getDocument 全页打分 top1 input。
